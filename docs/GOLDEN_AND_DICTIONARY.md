# 골든 테스트셋 · 동의어 사전 작성 가이드

검색 품질을 **측정**(골든)하고 **개선**(동의어 사전)하는 두 자산의 작성 노하우입니다.
샘플: [`tests/golden/cases_sample.yml`](../tests/golden/cases_sample.yml) · [`examples/dictionary.sample.yaml`](../examples/dictionary.sample.yaml)

---

## 1. 골든 테스트셋 (검색 품질 회귀 감시)

**형식** (`cases:` 리스트):
```yaml
cases:
  - query: "무중단 배포 절차"      # 검색 질의
    expected_title: "서버 배포 가이드"  # top_k 안에 있어야 통과
    top_k: 10                       # 정답 허용 순위(기본 10)
    notes: "기본형"
```

### 작성 노하우 — 같은 정답에 "어려운 쿼리"를 여럿
정답 제목·본문의 단어를 그대로 쓰면 너무 쉬워 회귀를 못 잡습니다. **표현을 비틀어** 실제 사용자/LLM의 다양성을 흉내냅니다.

**① 조사 복합형 — 한국어 형태 견고성**
어절 끝에 **조사를 강제로 붙입니다**: `배포` → `배포를`·`배포는`·`배포에서`.
- 왜: `unicode61` 토크나이저는 `배포를`을 한 토큰으로 봐 `배포`와 매칭 실패할 수 있습니다. 조사 정규화(색인·쿼리 양쪽에서 조사 분리)가 동작하는지를 이 케이스가 검증합니다.
- 한 정답에 원형 + 조사형 2~3개를 함께 둡니다.

**② 번역 왕복 — 어휘 다양성**
정답 본문/제목을 **영문으로 번역 → 다시 한글 → 20~40자로 요약**합니다.
- 왜: 왕복을 거치면 원문과 **다른 어휘**의 자연스러운 문장이 나옵니다(예: "무중단 배포" → *zero-downtime deployment* → "트래픽 끊김 없이 서버 교체"). 동의어·패러프레이즈에 검색이 견디는지 테스트됩니다.
- 원문 단어를 그대로 쓰지 않는 게 핵심입니다.

**③ LLM 방식 — 실 소비자 분포**
이 검색의 실제 호출자는 사람이 아니라 **LLM**입니다. 구어·불용어를 빼고 **핵심 명사구로 압축**한 쿼리를 넣습니다(예: "그 배포 문서 좀 찾아줄래?" → "무중단 배포 절차"). LLM은 top1~3만 소비하므로 `top_k`를 작게(3~5) 두면 정밀도를 더 엄격히 봅니다.

**④ 동의어 의존 케이스**
동의어 사전이 있어야만 통과하는 쿼리(예: "디플로이 방법" → 배포 문서)를 둡니다. 사전 적용 전후로 통과율이 바뀌어 **사전 효과를 측정**할 수 있습니다.

> 팁: `notes` 에 어떤 노하우(조사형/번역왕복/동의어)인지 적어두면, 실패 시 원인 분류가 쉽습니다.

### 반자동 초안 — `golden_bootstrap` (본문중심 질의 역생성)
빈 종이 대신, 문서에서 **본문중심 질의 초안**을 자동 생성하고 사람은 **검수만** 합니다(오프라인·무LLM, 규칙+통계).
```bash
python scripts/golden_bootstrap.py "<db1>,<db2>" --out golden.draft.yml -n 40 \
  [--self-check <db>]   # 현 검색기가 정답을 top_k 에 넣는지 주석만(필터 아님)
```
- **방법**: 문서를 골라 → **제목에 없는** 본문 단어 중 코퍼스에서 **희소(DF 낮은)** 한 것 N개로 질의 → 정답(`expected_title`)=그 문서 제목. 제목어를 빼므로 "제목엔 없고 본문에만 답" 인 **본문중심**(passage recall) 케이스가 된다.
- **거짓라벨 최소화**: DF 상한(`--max-df-ratio`)으로 흔한 단어 제외, 희소어 묶음으로 질의가 해당 문서에 고유해지도록.
- ⚠️ **반드시 검수**: 규칙 기반이라 한국어 조사·활용형 잔류("들로"·"써주세요" 등)·부자연 질의가 섞인다(형태소 분석기 미사용). `_source_doc_id`·`_terms`·`_self_check` 보조필드를 보며 다듬어 `tests/golden/` 으로 확정한다. `expected_title`(정답)은 자동이 보장하지 못하므로 **사람이 정답 유일성을 확인**한다.

## 2. 동의어 사전 (쿼리 확장으로 품질 개선)

**형식** (`~/.geryon/gold/dictionary.yaml`, 리스트):
```yaml
- term: 배포              # 쿼리에 이 말이 있으면
  synonyms: [deploy, 디플로이]   # 이 말들로도 확장 검색
  boost: 1.0              # 가중(중요 용어는 >1.0)
  scope: global           # global(전체) | user(개인)
```

> **양방향 매칭**: 쿼리에 `term` 이 있든 `synonyms` 중 하나가 있든, **그룹 전체로 확장**됩니다(공백 기준 토큰 정확 일치). 그래서 한 그룹에 표기·변형을 모두 모아 넣으면 어느 방향이든 동작합니다(예: `디플로이`로 검색해도 `배포` 문서가 잡힘).

### 작성 노하우 — "자주 틀리는 것"부터

**① 영–한 음차 동의어 (가장 효율 높음)**
기술 용어는 **영문·한글 음차가 섞여** 한쪽으로 검색하면 다른 쪽을 놓칩니다. **양방향 + 변형까지** 넣습니다.
| 개념 | synonyms 예 |
|---|---|
| Superset | `슈퍼셋`, `수퍼셋`(오타성 변형까지) |
| Druid | `드루이드` |
| Kubernetes | `쿠버네티스`, `k8s`, `쿠버` |
| GCP | `지씨피`, `Google Cloud` |
- 음차는 표기가 갈리므로(슈퍼셋/수퍼셋) **흔한 변형을 모두** 등록하는 게 핵심입니다.

**② 약어 ↔ 풀네임**: `K8s↔Kubernetes`, `CI↔지속통합`, `PR↔Pull Request`.

**③ 유의어·사내 용어**: `배포↔디플로이↔deploy`, `장애↔인시던트↔incident`.

**④ 우선순위 = 검색 로그의 zero-result·인기 쿼리**
모든 단어를 넣지 말고, **검색이 자주 실패하는 음차/약어**부터. 효율은 "자주 틀리는 것"에 집중할 때 가장 큽니다.

**⑤ boost**: 핵심 용어는 `boost > 1.0` 으로 상위 노출을 강화.

### 효과 측정 (필수)
동의어를 추가하면 **반드시 골든(특히 음차 쿼리)으로 전후 비교**합니다. 무작정 늘리면 노이즈로 오히려 정밀도가 떨어질 수 있습니다 — 측정으로 확인하세요.

### 자동 부트스트랩 (반자동 — 데이터에서 후보 추출)
빈 종이에서 쓰는 대신, **문서에 이미 병기된 표현**을 수확해 후보를 만듭니다(오프라인·규칙+통계, LLM 불필요).
```bash
python scripts/dict_bootstrap.py "<db1>,<db2>" --out ~/.geryon/gold/dictionary.auto.yaml
```
- **수확 대상**: 괄호 병기(`대한항공(KE)` → `KE↔대한항공`), 약어 빈출(`NDC·GDS·PNR` — 정의할 용어 식별)
- **noise 필터**: 흔한 단어(확인·제목)·코드필드(camelCase)·구문 자동 제외
- **한계**: 표기 변형(약어·음차)은 잘 잡지만, **의미 동의어**(`OOM↔메모리장애`)는 병기가 없어 못 잡음 → 수동으로

#### 수동 / 자동 / 제외 — 3파일 분리 관리
| 파일(`~/.geryon/gold/`) | 역할 |
|---|---|
| `dictionary.yaml` | **수동** — 사람이 관리, 같은 term 이면 **우선**. **항상 로드** |
| `dictionary.auto.yaml` | **자동** — `dict_bootstrap` 생성·갱신(재추출 가능). **기본 OFF**, `GERYON_DICT_AUTO=1` 일 때만 로드 |
| `dictionary.deny.yaml` | **제외** — 오수집을 **영구 무시** |

GoldSearch 는 **수동 사전을 항상 로드**하고, `GERYON_DICT_AUTO=1` 일 때만 자동 사전을 **병합(수동 우선)**합니다.

> **자동 사전이 기본 OFF인 이유**: `dict_bootstrap` 의 raw 출력에는 진짜 동의어와 노이즈(작성자명·우연 괄호매칭)가 섞여, **데이터에 따라 정확도를 떨어뜨릴 수 있습니다**(측정 예: 골든 87%→77%). 내 코퍼스가 동의어 연결에 적합한지 **골든으로 전후 측정**한 뒤(아래 워크플로우로 검수·deny 정제), 효과가 확인되면 `GERYON_DICT_AUTO=1` 로 켜세요. 재추출해도 수동 사전은 안전합니다.

**오수집 제외**: 잘못 잡힌 항목을 deny 에 등록하면, auto.yaml 을 다시 만들어도 무시됩니다(직접 지우면 재추출 때 되살아남).
```yaml
# dictionary.deny.yaml
terms:    [FE Refactoring, URL]      # 이 영문 term 제외
synonyms: [홍길동, 아무개]            # 이 한글 synonym 제외
```

**워크플로우**: ① `dict_bootstrap` → `auto.yaml` ② 검수: 남은 noise 를 `deny.yaml` 에 등록 ③ 재추출(deny 반영, 클린) ④ GoldSearch 자동 병합. — 세 겹 방어: *필터(자동) → deny(검수 영구) → 수동 우선(병합)*.

## 3. 적용
```bash
mkdir -p ~/.geryon/gold
# 수동 사전
cp examples/dictionary.sample.yaml ~/.geryon/gold/dictionary.yaml   # 편집해서 사용
# 자동 사전(선택): 데이터에서 부트스트랩 → 별도 파일
python scripts/dict_bootstrap.py "<db1>,<db2>" --out ~/.geryon/gold/dictionary.auto.yaml
# 개인 사전(선택): ~/.geryon/gold/users/<user_id>.dictionary.yaml
```
사전이 없으면 확장 없이 동작합니다. `dictionary.yaml`(수동) + `dictionary.auto.yaml`(자동)을 **병합 로드(수동 우선)** 하며, `dictionary.deny.yaml` 의 오수집은 자동에서 제외됩니다.
